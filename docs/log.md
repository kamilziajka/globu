* [globu-worker](./worker.md) splits a run into `prepare`, `execute` and `conclude` and exposes the deterministic ends as session commands: `poll`, `claim <key>` (claim, resolve, worktrees, brief, stop with the run `prepared`), `finish <run-id>` (push, pull requests, comment, cleanup) and `release <run-id> --reason`. They use the session's own Globu home, `~/.globu` by default, and the person's checkouts; a run they make has `driver: session` in `run.json`, keeps its worktrees in the record and gets a footer that names the session instead of turns and cost. The worker also sets `GLOBU_HOME` for the registry when the variable is unset, so the default home is read by `globu-core` too.
* Two session skills in the plugin, [described](./skills.md) with the rest: `issue-work` takes one issue in the current session with the person watching, through `claim`, `issue-deliver` and `finish`; `issue-watch` polls a project, claims up to `limits.concurrent`, runs one subagent per issue and finishes each. The READMEs and [architecture](./architecture.md) list eight skills.
* [globu-worker](./worker.md) after the first setup on a laptop: `GLOBU_HOME` defaults to `~/.globu/worker` and `CLAUDE_CONFIG_DIR` to `claude` inside it, with the interactive `~/.globu` and `~/.claude` still refused; `claimedStatus` and `releasedStatus` take a status id as well as a name, told apart by an all-digit value; a repository with no commits on its default branch releases the issue with a message that says so instead of a git error about `origin/HEAD`.
* The `claude` section of `worker.yaml` mirrors the `claude -p` flags: `maxTurns` and `maxBudgetUsd` moved there from `limits`, which keeps `concurrent`, `perShard`, `timeout` and `dayUsd`, the four things the worker enforces itself. The allowlist goes to the run as `--allowedTools` and the fixed deny list as `--disallowedTools`, so the run directory no longer holds a `settings.json`. The [hook contract](./claude-code-hooks.md) lists those flags among the untested behaviours in place of `--settings`.
* The `implement-issue` skill is `issue-deliver`, matching `issue-check`, `issue-fix`, the `deliverable` shards and the Ready for delivery status.
